# 캡처일정 (가칭) 기획서

대화 화면을 캡처하고 공유 버튼만 누르면, 젬마4가 캡처 속 대화를 읽고 날짜, 시간, 장소를 정리해서 저장해 주는 모바일 웹. 버튼 한 번으로 폰 캘린더에 넣어 알림까지 받는다.

---

## 1. 불편한 점

문자나 카톡으로 약속이나 마감이 생기면 어딘가에 적어 둬야 안 까먹는다. 그런데 나는 **메모 앱을 열고, 타이핑하고, 정리하는 과정 자체가 너무 귀찮다.** 그래서 "나중에 적어야지" 하고 미루다가 결국 까먹고 곤란해진 적이 많다.

- 지금은 JOT 같은 메모 위젯을 쓰고 있지만, 결국 **내가 직접 타이핑**해서 넣어야 하는 건 똑같다.
- 어쩌다 메모를 해 둬도 **그날 알려 주는 게 없으니** 다시 안 보게 되고, 결국 까먹는다. 캘린더에 넣으면 알림이 오지만, 캘린더에 날짜·시간·장소를 하나하나 입력하는 건 메모보다 더 귀찮다.

## 2. 해결 방법

**캡처 → 공유 → 이 앱. 터치 세 번으로 정리하고, 두 번 더 누르면 캘린더 알림까지.**

1. 대화 화면을 캡처한다.
2. 캡처 직후 뜨는 툴바에서 **공유**를 누르고, 이 앱을 고른다.
3. 젬마4가 캡처 속 대화를 읽고 일정(제목, 날짜, 시간, 장소)을 뽑아 **자동으로 저장**한다. 잘못 읽은 부분이 있으면 그 자리에서 고친다.
4. **[캘린더에 추가]**를 누르면 내용이 다 채워진 캘린더 새 일정 화면이 열리고, **[저장]**만 누르면 된다. **알림은 폰 캘린더에 맡긴다.**

캡처 한 장에 대화 흐름이 통째로 담기니까, 나눠서 온 메시지나 중간에 바뀐 약속도 젬마가 한 번에 읽고 **최종적으로 정해진 내용**을 골라낸다.

### 터치 수 비교

| 방법 | 과정 | 터치 |
|---|---|---|
| 메모 앱 / JOT | 메모 앱 열기 → 새 메모 → 대화 보고 직접 타이핑 → 저장 | 4번 이상 + **타이핑**, 알림 없음 |
| 캘린더 직접 입력 | 캘린더 열기 → 새 일정 → 제목·날짜·시간·장소 입력 → 저장 | 8번 이상 + **타이핑** |
| 메시지 복사 | (메시지마다) 꾹 → 복사 → 메모 앱 → 꾹 → 붙여넣기 | 메시지 3개면 **15번** 가까이 |
| **이 앱** | 캡처 → 공유 → 이 앱 (→ 캘린더에 추가 → 저장) | **정리 3번, 알림까지 5번. 타이핑 없음** |

### 불편 → 해결 연결

| 불편 | 해결 |
|---|---|
| 메모 앱을 열고 타이핑하는 게 귀찮다 | 캡처하고 공유만 하면 된다. 타이핑 없음 |
| 대화가 여러 메시지로 나눠서 온다 | 캡처 한 장에 대화가 다 담기고, 젬마가 합쳐서 읽는다 |
| 중간에 약속이 바뀐다 | 젬마가 대화 흐름에서 **최종 합의된 내용**을 고른다 |
| 메모해 둬도 알려 주는 게 없어서 까먹는다 | [캘린더에 추가] → [저장] 두 번이면 폰 캘린더에 들어가고, 캘린더가 때맞춰 알려 준다 |
| 캘린더에 직접 입력하는 건 더 귀찮다 | 캘린더 새 일정 화면이 이미 채워진 채로 열린다 |

## 3. 범위

| 하는 것 | 하지 않는 것 |
|---|---|
| 캡처(이미지) 공유받기, 여러 장 한 번에 | 홈 화면 위젯 |
| 갤러리에서 직접 올리기 (공유가 안 될 때 대체) | 캡처를 자동으로 감지해서 처리하기 |
| 일정 추출, 자동 저장, 수정, 삭제 | 앱이 직접 알림 보내기 (알림은 폰 캘린더가 담당) |
| 다가오는 순 목록, D-day | 폰 캘린더와 자동 동기화 (버튼으로 한 건씩 추가) |
| [캘린더에 추가] 버튼 | 아이폰 (사파리는 공유받기를 지원하지 않음) |
| 안드로이드 크롬에 홈 화면 설치 (PWA) | 로그인, 여러 사용자 |

## 4. 사용 흐름

### 4-1. 처음 한 번

1. 폰 크롬으로 앱 주소(HTTPS 고정 주소)를 연다.
2. 메뉴 → **홈 화면에 추가(앱 설치)**. 이때부터 공유 메뉴에 이 앱이 뜬다.

### 4-2. 일정 저장

```
대화 화면 캡처
  → 캡처 툴바 [공유] → [캡처일정]
  → (잠깐 로딩) 젬마가 읽는 중...
  → 결과 화면
      ✅ 저장했어요
      ┌────────────────────────────┐
      │ 팀플 회의                    │
      │ 11/18 (수) 19:00 · 강남역    │
      │ [캘린더에 추가] [수정] [삭제] │
      └────────────────────────────┘
      [목록 보기]
  → [캘린더에 추가] → 채워진 새 일정 화면 → [저장]
```

- 캡처에 일정이 여러 개면 여러 개를 저장한다. [캘린더에 추가]는 일정마다 있다.
- 날짜, 시간, 장소 중 못 찾은 것은 빈칸(`?`)으로 저장하고 결과 화면에서 표시한다.
- 일정이 없는 캡처면 "일정을 찾지 못했어요"를 보여 주고 아무것도 저장하지 않는다.

### 4-3. 공유가 안 될 때 (대체 방법)

앱을 열고 [사진 올리기] → 갤러리에서 캡처 선택. 이후 과정은 같다.

### 4-4. 일정 보기

홈 화면 아이콘 → 목록. 다가오는 일정이 위에 오고, 지난 일정은 아래에 흐리게 보인다.

```
D-1   11/18 (수) 19:00  팀플 회의 · 강남역
D-3   11/20 (금) 23:59  자료구조 과제 마감
D-10  11/27 (금) ?      동아리 MT · 가평
```

## 5. 젬마4 처리

### 5-1. 입력

- 캡처 이미지 (여러 장이면 한 요청에 같이)
- **오늘 날짜와 요일** (상대적 날짜 계산용)

### 5-2. 출력 (JSON)

```json
{
  "events": [
    {
      "title": "팀플 회의",
      "date": "2026-11-18",
      "time": "19:00",
      "place": "강남역",
      "note": "처음엔 6시였다가 7시로 바뀜"
    }
  ]
}
```

| 필드 | 형식 | 못 찾으면 |
|---|---|---|
| `title` | 짧은 제목 | 대화 내용으로 짐작해서 작성 |
| `date` | `YYYY-MM-DD` | `null` |
| `time` | `HH:MM` (24시간) | `null` |
| `place` | 장소 이름 | `null` |
| `note` | 참고할 내용 한 줄 | 빈 문자열 |

일정이 없으면 `{"events": []}`.

### 5-3. 프롬프트에 넣을 규칙

1. **최종 합의된 내용**을 고른다. 중간에 바뀐 시간이나 장소는 마지막 것을 쓴다.
2. **날짜 기준**: "내일", "다음 주 화요일"은 오늘이 아니라 **그 메시지를 보낸 날** 기준이다. 화면에 날짜 구분선(예: "2026년 11월 16일")이나 "어제" 표시가 있으면 그걸 쓰고, 없으면 오늘 기준으로 한다.
3. 화면에 없는 정보는 지어내지 않고 `null`로 둔다.
4. JSON만 답한다.

### 5-4. 코드가 하는 일

- 젬마 답에서 JSON 꺼내기 (수업 자료의 `parse_json`)
- 날짜·시간 형식 검사. 형식이 틀리면 그 칸을 `null`로 바꾼다
- 저장, D-day 계산, 다가오는 순 정렬
- [캘린더에 추가] 링크 만들기 (아래 7장)

## 7. 기술 구성

| 항목 | 선택 | 이유 |
|---|---|---|
| 형태 | Flask 모바일 웹 + PWA | 수업에서 쓴 방식. 공유 메뉴 등록은 PWA로 해결 |
| 코드 작성 | VS Code + Cline (모델: 실습 서버 gemma4) | 과제 조건 |
| 모델 호출 | `https://krchoi.com/gemma4/v1`, 모델 `gemma4`, 수업 자료의 `ask()`·`parse_json()` 그대로 사용 | 브라우저에서 직접 부르면 막히므로 Flask가 대신 부른다 |
| 저장 | SQLite (`schedule.db`) | 일정 결과만 저장. 캡처 이미지는 저장하지 않는다 |
| PWA | `manifest.json` (+ `share_target`), 서비스 워커, 아이콘 | 홈 화면 설치와 공유 메뉴 등록에 필요 |
| HTTPS | **ngrok 무료 고정 도메인**으로 PC의 Flask를 공개 | PWA 설치와 공유받기는 HTTPS에서만 동작한다. 설치된 앱과 공유 메뉴는 **설치할 때의 주소에 묶이므로**, 켤 때마다 주소가 바뀌면 다시 설치해야 한다. 그래서 고정 주소를 쓴다 |
| 캘린더 | 구글 캘린더 일정 추가 링크 (`calendar.google.com/calendar/render?action=TEMPLATE&text=…&dates=…&location=…`) | 앱 없이 링크 하나로 채워진 새 일정 화면을 연다 |
| 확인 | PC 크롬 기기 모드 → 실제 안드로이드 폰 크롬 | |

### 공유받기 구조

`manifest.json`에 다음을 넣는다. 공유 메뉴에서 이 앱을 고르면 크롬이 캡처를 `POST /share`로 보내고, Flask가 `request.files.getlist("images")`로 받는다.

```json
"share_target": {
  "action": "/share",
  "method": "POST",
  "enctype": "multipart/form-data",
  "params": {
    "files": [{ "name": "images", "accept": ["image/*"] }]
  }
}
```

### 캘린더 링크 규칙

| 상황 | 처리 |
|---|---|
| 날짜, 시간 다 있음 | 그 시각부터 1시간짜리 일정 |
| 날짜만 있음 | 종일 일정 |
| 날짜 없음 | 버튼을 누르면 "날짜를 먼저 채워 주세요" 안내 |

### Cline 사용 원칙 (수업 자료에서 배운 것)

- 서버 주소와 호출 코드는 프롬프트에 그대로 넣어 준다.
- **모델이 잘 모르는 부분은 뼈대를 프롬프트에 직접 넣는다.** 특히 위의 `share_target` 설정과 `/share` 라우트, 캘린더 링크 형식.
- "답에 코드를 적지 말고 파일을 만든다", "`python app.py`는 실행하지 않는다"를 붙인다.
- 한 번에 한 기능만 요청한다. 멈추면 취소하고 같은 프롬프트로 새 작업을 보낸다.
- Cline에 보낸 프롬프트는 진행 기록에 남긴다.

## 8. 단계별 계획과 테스트

각 단계는 테스트를 통과해야 다음 단계로 넘어간다. 테스트 결과는 `PROGRESS.md`에 남기고, 단계마다 커밋한다.

**순서의 원칙**: 이 앱의 핵심이면서 가장 불확실한 **공유받기를 2단계에서 먼저 확인**한다. 안 되면 일찍 대체 방법(사진 올리기)으로 방향을 잡는다.

| 단계 | 하는 일 | 테스트 | 통과 기준 |
|---|---|---|---|
| 1 | 캡처 → 젬마 → 일정 JSON (파이썬 스크립트) | 평가용 캡처 25장으로 정답과 비교 (아래 참고) | 일정 있는 캡처 20장 중 날짜·시간 모두 맞음 **16장 이상**, 일정 없는 캡처 5장에서 가짜 일정 **1개 이하** |
| 2 | **공유받기 최소 확인**: 기능 없는 Flask + ngrok 고정 도메인 + 홈 화면 설치 + `/share`가 받은 사진의 장수와 크기만 표시 | 폰에서 캡처 → 공유 → 이 앱. ngrok 경고 페이지가 공유 요청을 가로채지 않는지. PC 서버를 껐다 켜도 주소가 같고 설치한 앱이 그대로 동작하는지 | 공유 메뉴에 앱이 뜨고, 화면에 "사진 1장, 1080×2400" 같은 결과가 나옴 |
| 3 | 1단계 추출 연결: 공유 / 사진 올리기 → 추출 → 자동 저장 → 결과 화면 | 폰에서 평가용 캡처 5장을 공유와 사진 올리기로 각각 넣기 | 1단계와 같은 결과가 화면에 나오고 DB에 저장됨 |
| 4 | 수정, 삭제, 목록 (정렬, D-day) | D-day와 정렬 함수 단위 테스트 (오늘, 내일, 지난 날짜, 날짜 없음), 폰에서 수정·삭제 | 단위 테스트 전부 통과, 수정·삭제가 목록에 반영됨 |
| 5 | [캘린더에 추가] | 링크 만드는 함수 단위 테스트 (날짜+시간, 날짜만, 날짜 없음), 폰에서 눌러 보기 | 단위 테스트 통과, 폰에서 채워진 새 일정 화면이 열리고 저장하면 캘린더에 들어감 |
| 6 | 예외 처리 | 일정 없는 사진, 풍경 사진, 캡처 여러 장, 아주 큰 이미지, 젬마 서버 응답 없음 | 오류 화면 없이 안내 문구가 나옴 |
| 7 | **최종: 전체 흐름 시연** | 실제 대화 5개로 캡처 → 공유 → 결과 확인 → 캘린더 저장까지 한 번에. 터치 수와 걸린 시간 측정 | 9장의 성공 기준 모두 만족, 화면 녹화로 기록 |

2단계에서 공유받기가 끝내 안 되면, 사진 올리기 방식으로 3단계 이후를 진행하고 안 된 이유를 기록한다.

### 평가용 캡처 (1단계)

| 종류 | 장수 | 예시 |
|---|---|---|
| 한 메시지에 다 있음 | 5 | "내일 7시 강남역에서 봐" |
| 여러 메시지로 나눠 옴 | 5 | "내일" / "강남역" / "7시 ㄱ" |
| 중간에 바뀜 | 4 | "7시 어때?" → "8시로 하자" → "ㅇㅋ" |
| 일정 여러 개 | 3 | 과제 마감 + 회의 |
| 날짜 기준이 오늘이 아님 | 3 | 날짜 구분선이 "어제"인 대화에서 "내일" |
| 일정 없음 | 5 | 잡담, 풍경 사진 |

- 본인 대화 캡처를 쓰되, 이름·프로필 사진·전화번호는 가린다. 부족하면 직접 대화를 만들어 캡처한다.
- 정답은 `answers.json`에 적어 두고, 프롬프트를 바꿀 때마다 같은 캡처로 다시 측정한다.

## 9. 성공 기준

- 캡처부터 저장 완료까지 **터치 3번**, 캘린더 저장까지 **터치 5번**, **타이핑 0번**
- 공유 후 결과 화면까지 **20초 이내**
- 1단계 정답률 기준 통과

## 10. 개인정보

- 사용자가 **직접 공유한 캡처만** 처리한다. 갤러리를 자동으로 읽지 않는다.
- 캡처는 실습 서버(젬마4)로 전송된다. 캡처에는 상대방 이름, 프로필 사진, 다른 대화도 함께 찍힐 수 있다.
- 캡처 이미지는 저장하지 않고, 뽑아낸 일정만 저장한다.

## 11. 한계

- **위젯이 없다.** 일정은 홈 화면 아이콘으로 열어 보거나, 캘린더에 넣어 알림으로 받는다.
- **PC의 Flask 서버와 ngrok이 켜져 있어야 한다.**
- **안드로이드 크롬 전용이다.** 아이폰 사파리는 공유받기를 지원하지 않는다.
- **젬마가 잘못 읽을 수 있다.** 그래서 결과 화면에서 바로 고칠 수 있게 했다.
- 대화가 캡처 한 장에 안 들어가면 여러 장을 같이 공유해야 한다.
- 캘린더 추가는 구글 캘린더 기준이다. 폰에서 앱으로 열리는지 웹으로 열리는지는 5단계에서 확인한다.
